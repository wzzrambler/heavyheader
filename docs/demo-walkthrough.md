# 三分钟演示脚本：一个问题，四步走完

> 这份脚本解决评审提的第三个问题：**评委能不能在几分钟内看懂价值**。
> 它的目的是防止演示变成「编译器参数介绍」——所以全片只讲**一个真实问题**，
> 四步都落在同一个工程、同一组数字上，每一步的结论都能被下一屏验证。

## 一句话主张

> 构建慢的时候，团队通常知道「大概是头文件太多」，但不知道**哪一个、值多少**。
> HeavyHeader 把「该不该动手」变成一次扫描，把「动了有没有用」变成一次重建。

## 准备（演示前跑一次，约 6 分钟）

```bash
cd heavyheader
python experiments/fetch.py            # 拉取固定快照 nlohmann/json v3.11.3
python experiments/run_experiment.py   # 生成下面要指的全部数字
```

演示时只需要**已经生成好的报告**和一个终端窗口，不现场等构建。

## 第一步：发现成本热点（0:00–0:50）

```bash
heavyheader scan experiments/_work/json --pch --pch-top 5
```

指屏幕上这两处就够，不要念全部输出：

- **头文件解析量 10,872,819 行**、依赖边 41,408 —— 63 个编译单元，平均每个要解析 17 万行头文件；
- 排名第一的 `doctest.h` 归因 **447,678 行**：它自己只有 7,106 行，乘以 63 个单元就是这个数。

> 口播：「注意这个数字不是头文件有多大，是**它被重复解析了多少**。
> 一个头在 63 个单元里各解析一遍，成本就乘 63。」

## 第二步：定位到具体 include（0:50–1:30）

```bash
heavyheader verify experiments/_work/json --top 5
```

这一屏的作用是回答「那删掉它行不行？」。逐个候选给出**实测**结论：

- `compile-error` —— 删了编不过，如实报告，不猜；
- `no-change` —— 差异在 2% 噪声内，不算收益；
- `improved` —— 给出基线/移除后的毫秒数。

> 口播：「这一步是工具肯认错的地方。它不是『建议你删』，它是真的删掉再编译给你看。
> 编不过就写编不过。」

## 第三步：验证收益（1:30–2:30）

切到 `experiments/results/experiment-20261017.md`：

| 指标 | 基线 | 加 PCH | 结果 |
|---|---:|---:|---|
| 完整构建（墙上时间中位数） | 43.2 s | 40.1 s | **节省 7.1%** |
| 编译 CPU | 292 s | 259 s | **节省 11.4%** |

然后指**估算 vs 实测**那张表：

- 估算说「消掉 91.2% 的头文件解析量」；
- 实测说「编译 CPU 省 11.4%」。

> 口播：「这两个数不一样，我们不合并它们。差在三处：16 个单元改了配置宏用不了 PCH；
> 头文件解析只占编译时间的一部分；估算按行数算，行数不是秒数。
> 反推下来，这个工程里头文件解析约占编译 CPU 的 17%——所以 11% 就是能拿到的全部。」

再切到**正确性门禁**：63 个测试套件、4,264,414 条断言，逐个与基线一致。

> 口播：「加速的前提是没改变语义。断言数逐套件对齐，少一条就不算通过。」

## 第四步：阻止回归（2:30–3:00）

```bash
heavyheader gate experiments/_work/json --baseline experiments/_work/baseline.json
echo "exit=$?"
```

改成 `--max-regression 0` 就能把它挂进 CI：谁再往公共头里塞东西、让归因行数上涨，PR 直接红。

> 口播：「这一行是这件事能不能长期成立的关键。优化一次不算本事，
> 不让它退回去才算——所以成本是有基线的，有门禁的。」

## 常见提问的答法

| 提问 | 答 |
|---|---|
| 这和 IWYU 什么关系？ | 互补。IWYU 判**正确性**（AST 级，能删不能删）；我们判**成本**（这条 include 让你多等几秒）。 |
| 为什么不直接上 PCH/ccache？ | 它们都是「怎么加速」；我们回答「**加速哪里**」。本实验里正是工具的归因数据指向了 PCH 该放什么。 |
| 91% 是不是吹的？ | 91% 是**行数占比**，标了「上限、不是秒数」。实测 11.4% 在同一张表里，两个数从不合并。 |
| 只测了一个工程？ | 是，如实写在局限里。单机、单编译器、单工程，可迁移性只到「量级」。 |
