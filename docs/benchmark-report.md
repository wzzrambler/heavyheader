# 基准报告 · 阶段 0：噪声底与确定性

> 日期：2026-10-18。本报告只报告**已测到**的东西；没测到的明确写「阻塞」。
> 复现：`python experiments/aa_noise.py --runs 3 --tus 25`
> 原始数据：`experiments/results/aa-20261018.{md,json}`

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 结构指标是否确定？ | **是**。归因行数 4,233,937，三次运行完全一致；Top-10 列表也一致 |
| 计时噪声底多大？ | 单 TU 墙钟极差中位 **1.58%**；整轮扫描 0.89%；编译合计 1.50% |
| 扫描开销多少？ | 扫描 41.64 s vs 编译合计 35.47 s，**1.17×** |
| G1（公平对照）是否通过？ | **没有**。本机缺 Clang / CMake / MSVC，CBA、Build Insights、IWYU 均无法运行 |

一句话：**我们自己重复自己的误差已经量出来了，但还没有和竞品同台。**

## 1. 方法

- 工程：`experiments/_work/json`（nlohmann/json），编译数据库 63 条，取前 25 个 TU。
- 命令：`heavyheader scan --compile-commands … --max-tus 25 --jobs 1 --format json`。
- 同一输入、不改任何文件，重复 3 次；`--jobs 1` 降低并行调度噪声。
- 记录：归因行数、Top-10 项目头、整轮扫描墙钟、TU 墙钟合计、逐 TU 墙钟。

## 2. 结果

| 指标 | 数值 |
|---|---:|
| 编译单元 | 25（0 失败） |
| 归因行数 | 4,233,937 × 3，完全一致 |
| 扫描墙钟中位数 | 41.64 s |
| 扫描墙钟极差 | 0.89% |
| TU 墙钟合计中位数 | 35.47 s |
| TU 墙钟合计极差 | 1.50% |
| 单 TU 墙钟极差（中位） | **1.58%** |
| 扫描 / 编译 | 1.17× |

**判读**：任何声称「省了 1.5% 以内」的优化，在本机都不可区分于噪声。
`verify` 的噪声线（`TIME_NOISE_FLOOR`）应不低于这个量级——这一点要在 G2 里核对。

## 3. 本轮抓到的缺陷：Top-10 曾经不稳定（已修）

第一次 A/A 跑出来：归因行数三次完全一致，但 **Top-10 列表三次不同**。

- 根因：`header_stats` 的插入顺序来自 `set` 迭代，而 `Path` 的哈希受 Python
  哈希随机化影响；排序键只有 `(归因行数, 覆盖 TU 数)`，并列时顺序由迭代顺序决定。
- 影响：任何「与竞品 Top-10 一致性」的对比都会把随机差异算成算法差异；
  基线 diff 也会出现假变化。
- 修复：排序键加路径作为最终 tie-breaker；`header_stats` 按路径排序后迭代；
  JSON 导出按路径排序。附回归测试。
- 复验：三次运行 Top-10 完全一致。

这类缺陷不会崩溃、数字也「看着合理」，只有 A/A 对照能抓到——这正是先做噪声底的价值。

## 4. 另一个口径问题：仓库内的第三方头

Top-1 是 `doctest.h`（`tests/thirdparty/` 下的测试框架，vendored 进仓库）。
当前分类规则是「路径在 root 下即视为项目头」，因此它被当成可治理对象。

这对 G1 不公平：竞品可能把它归为第三方。**在对照前必须先统一分类口径**，
否则「谁的 Top-1 是什么」根本不可比。已记为待决项（见 §6）。

## 5. 阻塞项（本机环境，非产品缺陷）

| 对照工具 | 阻塞原因 | 影响 |
|---|---|---|
| ClangBuildAnalyzer | 无 `clang++` / `cmake`，且需要 Clang 9+ 与 `-ftime-trace` | G1 的 Clang 侧无法进行 |
| 微软 C++ Build Insights | 无 MSVC / Visual Studio | R6（MSVC 未实测）无法关闭 |
| IWYU / Include Cleaner | 无 `clang++` | 「与 AST 工具比候选质量」无法进行 |

这三项都必须在有对应工具链的机器上补测；本轮不伪造任何对照数字。

## 6. 下一步（按优先级）

1. **统一分类口径（决定：不改产品语义，改基准协议）**：`HeaderKind` 的文档明确
   警告不要把 kind 当候选过滤器（早期版本因此错过有效建议）。因此不在产品里新增
   “vendored” 分类，而是在对照协议中显式用 `--exclude` 排除
   `tests/thirdparty/**`、`vendor/**`、`external/**`，并把排除规则写进结果文件。
   这样两边比较的是同一批文件，且不改变工具对真实用户的判定逻辑。
2. **在有 Clang 的机器上**：跑 `-ftime-trace`，用同一批 TU 与我们的热点排序做
   一致率对比；同时记录 CBA 的采集成本。
3. **G2 校核**：把 §2 的 1.58% 噪声底与 `verify` 的 `TIME_NOISE_FLOOR` 对照，
   确认判定阈值不低于实测噪声。
4. **MSVC 工程**：补 R6，重点看「Build Insights 已有信息之外，我们减少了多少人工步骤」。
